# M6: 1.0

M6 closes the known gaps that stand between the project and its first release, adds engine preloading, and publishes
1.0. Every gap it resolves was marked "fix" in a review of `docs/known-gaps.md`; the rest stay listed there as accepted
or deferred. Two pieces of work that came out of that review are left for later milestones: the shared content-addressed
store, and learning in every tab through per-tab user databases merged with Rime's sync and a merging save in Mozc.

The milestone has five phases. 6a and 6b change the protocol, the module ABI and the public API, so they land before
anything is published; 6c and 6d are independent of each other; 6e can run beside any of them, and the release comes
last.

## Goals

- No silent loss of a user's data: a module that can't write its user data says so and works without it, and no recovery
  path deletes what it can't open.
- Engine failures reach the host as typed errors with their reason and diagnostic, from calls and from module state.
- An engine's C++ exception ends only its module, cleanly.
- Keyboard layouts tested beyond US, with a per-engine layout override a host can drive from its own detection.
- m17n starting without reading every input method, and Rime's settings changes without recompiling every schema.
- A host able to fetch, and optionally install, the engines it will want before it selects them.
- CI on WarpBuild runners and more platforms, real Safari covered, and npm releases through Changesets.

## Non-goals

- The shared content-addressed store (`docs/known-gaps.md`, Storage). It is a new subsystem, with its own milestone and
  spec.
- Learning in more than one tab of a module at once. A read-only tab works without learning (6a); per-tab user databases
  merged through Rime's sync and a merging save in Mozc come later.
- Pasting or opening find from the page: a page can neither read the clipboard nor open the browser's find, so a
  declined shortcut queued behind a key keeps losing those two.
- Detecting the system keyboard layout. The override and the engine's declared layout are enough for a host to do it
  with `navigator.keyboard.getLayoutMap()`.
- A runtime ABI or protocol version other than 1. Nothing has been published, so the first publish is version 1.

## 6a: Data safety and storage

### Read-only modules

One host per module holds the writer lock (`ibus-web:writer:<name>`); any other mounts the module's user data read-only
and posts `storage: read-only`. Init tells the module whether its user data is writable.

- **Rime** opens no user dictionaries when read-only. librime's `UserDictionary::Load` otherwise fails at LevelDB's
  `LOCK` file, schedules `userdb_recovery_task`, the task fails, and the module ends every session on that failure, so
  each new session repeats it: compositions are cut off and nothing learned shows. A read-only Rime types from its
  shipped dictionaries alone, schedules no recovery and never resets sessions for it.
- **Mozc** turns off saving its history and user dictionary when read-only. It still loads the writer's data as of its
  start.
- The `storage: read-only` event is documented for pages as "learning is off in this tab".

### Rime's recovery

When LevelDB fails to open a user dictionary, librime's recovery task repairs it, and if that fails renames it to `.old`
and starts empty, restoring only from a sync snapshot that nothing here makes; a second failure deletes the live
database. A port patch changes that:

- An open that fails with an I/O error (`EIO`, `ENOSPC`, IndexedDB closing) disables that dictionary for the session and
  logs a warning. Nothing is renamed or deleted.
- Only LevelDB's `Corruption` status leads to `RepairDB`. A failed repair moves the database aside under a timestamped
  name and starts empty; it never deletes one.

### Held log writes

The module holds a user dictionary's `.log` writes until input pauses (`docs/rime.md`, Learning). A held write that
fails is kept as an error and returned from the file's next `Sync` or `Close`, so LevelDB enters its error state as it
would for a write that failed during a key.

### Stored settings a module's schema rejects

Modules can declare different schemas at one settings path, and a record stored by one may be outside another's type,
choices or range. Today that fails the other module's `Init` snapshot and `get`. Instead, the module's settings backend
skips the record, uses the schema's default and emits one `Log` warning naming the path and key; live changes already
skip such values.

### m17n's Init

`Init` declares every settings instance a module has; m17n's 232 come to 22,378 bytes of the 64 KiB request slot with
nothing stored, so a user who stores many values could push `Init` past the slot and fail the module's start. A module
declares relocatable settings by path pattern (`/org/freedesktop/ibus/engine/m17n/{lang}-{name}/`) and the schemas that
apply, and `Init` carries only the instances that have stored values. An `Init` that still exceeds the slot fails with a
`ProtocolError` naming the size.

### Closed storage

The host notices a closed IndexedDB connection only when it next wakes. The page listens for `versionchange` on the
module's databases and wakes the host through the relay, so `storage: closed` is posted at once.

### Memory fallback headroom

Without IndexedDB, memory grows by the page-rounded size of the data, which covers file contents but not WasmFS's file
objects and directory entries. The manifest gains each archive's file count, and the headroom adds a per-file allowance
measured from WasmFS.

### Host storage API

As §5.6 and §8 of the design spec describe, on the facade's `storage` object:

- `usage()`: per module and engine, data and user data separately, in bytes.
- `export(module)`: the module's user data as a tar `Blob`, from a read-only snapshot taken through the writer.
- `reset(module)`: clears the module's user data; the module restarts.
- `storage` events of kind `quota` when a write fails with `ENOSPC`, naming the module.

## 6b: Runtime and API before release

### Tagged errors

Core defines the design spec's errors as Effect `TaggedError`s: `EngineLoadFailed`, `RuntimeAbiMismatch`,
`ProtocolMismatch`, `EngineCrashed`, `EngineHung`, `ProtocolError` and `StorageUnavailable`. `CreateEngineError` and
`PrepareEngineError` join the same family. Each carries `module`, `engine` where one applies, a `reason` (`TRAP`,
`FAULT`, `RELAY`, `LOAD`, `HOST` for a crash) and the Worker's diagnostic.

- The facade exposes them as `Error` subclasses with `_tag`, exported from `ibus-web`; `ibus-web/effect` exports the
  tagged errors themselves.
- Calls (`select`, `prepare`, `preload`, `engines`, the settings and storage calls) reject with them.
- Crashes and hangs happen without a call to reject, so the `modulestate` event's detail gains `error`, set with
  `restarting` and `failed`.

### C++ exceptions

An engine's exception unwinds through GLib's signal emission, so the runtime latches a fault and every later dispatch
fails. A GLib patch adds a dispatch hook around the `marshal` call in `g_closure_invoke` and `_g_closure_invoke_va` and
the source dispatch in `g_main_dispatch`. libibus-web sets it to a C++ `try`/`catch` trampoline, so GLib's bookkeeping
completes, the exception is caught, and only the engine module is marked faulted. The host ends the module with
`EngineCrashed` (`FAULT`) and restarts it as for a trap; the runtime itself stays usable until then, so its output is
drained and the diagnostic carries the exception's `what()`.

### Module shutdown

A module's init may register a shutdown function with `ibusweb_module_set_shutdown(module, fn)`, as it registers its
persist function. On `unload` and `dispose()` the host sends `Persist`, then a new `Shutdown` request that calls each
module's function in reverse registration order. Hangul's `ibus_hangul_exit` runs from it.

### ABI identity

Manifests compare only the numeric runtime ABI. The runtime's export manifest gains an identity hash over the linked
libraries' versions and the export list; each engine manifest records the hash it was built against, and a mismatch
fails the load with `RuntimeAbiMismatch`. The numeric ABI stays 1.

### Startup and memory

- Each pool Worker runs one empty thread when the module starts, so Chromium's first-thread cost, about 12 ms each,
  never falls in a key.
- The per-Worker memory figures are re-measured against the final host and runtime.
- `heapBytes` is measured from the heap's base, not as a break address, so the manifest's `memory` stops counting the
  static data twice.

### Exports and the wake hook

- The backend's internals (`_wasmfs_idb_record_entry`, `_wasmfs_idb_set_string`) stop being exported to side modules.
- The wake hook (GLib patch 0017) refuses a `NULL` hook whatever `G_DISABLE_CHECKS` says, documents that a context must
  outlive concurrent wakeups, and its smoke test's counter becomes atomic.

## 6c: Input fidelity

### Layout matrix

Playwright specs send real `key`, `code` and modifier combinations for US, AZERTY, QWERTZ, Dvorak and Colemak, covering
AltGr characters, dead keys (which reach no engine) and Ctrl and Meta shortcuts, through every engine in all three
browsers. What they find is fixed, and `docs/core.md` records the behaviour per layout.

### Layout override

- Each engine gets a `layout` setting, `"us"` or `"default"`, stored through the settings API like any other and applied
  live.
- `engines(module)` reports each engine's declared layout beside it.
- A host that detects layouts reads `navigator.keyboard.getLayoutMap()` and sets the setting; no other API is needed.

### Declined shortcuts

A shortcut queued behind a key in flight, then declined by the engine, loses its browser action unless the adapter
performs it. The textarea adapter performs word deletion and caret and word navigation itself through the Selection API,
beside the undo, redo, select-all, cut and copy it already performs. Paste and find stay browser-only and are
documented.

### Smaller fixes

- The surrounding text's selection anchor moves with the IBus-compatible delete, not at the next `SetSurroundingText`.
- Hangul's `preedit-mode` takes effect in an existing engine at once, not at refocus.

## 6d: Startup and preloading

### m17n's index

The Nix build runs m17n natively over the shipped database and writes an index of every input method: name, language,
title, description and icon. An ibus-m17n port patch makes the listing read it, and an input method's `.mim` is parsed
only when its engine is made. A check compares the index with what the listing would read from every `.mim`, and startup
is measured in the browsers.

### Rime's settings changes

- A settings change compiles only the schemas whose engines are open. Every other installed schema is marked stale and
  compiled when its engine is next made or its dictionaries finish installing, which also gives a dictionary installed
  later the current prisms.
- Page size applies to running sessions without a recompile, through a module patch that sets the menu's page size on
  each session; only `switcher-hotkeys` and `ascii-toggle-key` recompile.

### Preloading

`preload(entries, options?)` on the facade, `entries` being `{ module, engine? }` items:

- **Fetch (default).** When the page is idle, the manifest, the `.wasm` and the data archives of each entry (a module's
  base data, and an engine's own when `engine` is given) are fetched at low priority into a Cache Storage cache owned by
  ibus-web, keyed by URL and the manifest's content hash. The Worker's fetches look there first. No Worker starts and no
  storage is opened.
- **`install: true`.** When idle, a short-lived Worker per module installs the data into IndexedDB and exits, so the
  first selection only starts the module. It needs the module's writer lock and skips a module another tab holds.
- `preload` events carry `{ module, engine, bytes, total }` like `install` events. The returned Promise settles when
  every entry is fetched or installed, and rejects with the tagged errors.
- Superseded versions' cache entries are deleted when their module next starts, as old databases already are.

## 6e: CI and release

### Runners

- Linux jobs move to WarpBuild runners, as other Synapdeck projects use, which also ends the cold-run disk problem.
- `nix flake check` runs on aarch64-linux and aarch64-darwin as well as x86_64-linux. The release builds on x86_64-linux
  only: its outputs are WebAssembly and JavaScript, the same everywhere.

### Safari

Playwright drives its own WebKit build, not Safari.

- The whole Playwright suite also runs on a macOS runner, whose WebKit is closer to Safari's than Linux's.
- A smoke suite drives real Safari through `safaridriver` and WebDriver on the same runner: Hangul typing, a Rime
  install and conversion, learning that survives a reload, and the IndexedDB backend in Workers (R5, R13).

### Releases

Changesets versions the packages and writes their changelogs. On a tag, the release workflow builds `.#release`, creates
the GitHub release with its assets and publishes every npm tarball with trusted publishing, as §10.5 of the design spec
describes.

### Toolchain fixes

- **Single-file executables.** The compiler wrapper's hook adds `-sSINGLE_FILE` ahead of the command's own arguments on
  every link that makes an executable: not a compile, not `-shared`, not `-sSIDE_MODULE`. The runtime opts out with
  `-sSINGLE_FILE=0`, since browsers compile a separate `.wasm` while it streams and cache it. Recipes that copy `.wasm`
  files beside their executables drop that step. A toolchain check links a plain executable and a main module that loads
  a side module, and asserts each produces no `.wasm` and runs under Node.
- **Autotools configure checks** run their test programs through a Node exe wrapper, as Meson's do.
- **`.emcache`** in the dev shell is re-seeded when the frozen cache's hash changes.
- **The files writer** records the files it manages and deletes one it no longer configures.

## Testing

Each phase's checks run in `nix flake check` and `integration-checks`; the new ones are:

- 6a: a read-only Rime and Mozc under Node (no recovery task, no session reset, typing works), Rime's recovery on an
  injected `EIO` and on a corrupted log, a failed held write, a rejected stored record, an `Init` with many m17n
  instances, `storage: closed` without a wake, and the storage API in the browsers.
- 6b: each tagged error from a call and on `modulestate`, a C++ exception thrown by a test engine (the runtime stays
  usable until the restart), a shutdown function's order, an ABI identity mismatch.
- 6c: the layout matrix, the override, the adapter's word deletion and navigation.
- 6d: the m17n index check and start times, Rime's lazy compiling and live page size, both preload modes.
- 6e: the single-file check, the macOS Playwright run and the Safari smoke suite.

## Delivery

One plan per phase, in `docs/plans/`. Before the release: `nix run .#write-files` with no drift, `nix flake check`,
`nix build .#integration-checks` and `hk check --all` on every platform CI checks, the Safari smoke suite, and
`docs/known-gaps.md` holding only what was accepted or deferred. The design spec's milestone table records M6, and the
next milestones are the content-addressed store and learning in every tab.

## Risks

- The dispatch hook in GLib adds a C++ frame to every signal emission and source dispatch; its cost on the keystroke
  path is measured, and if it shows, the hook is limited to engine signals.
- `-sSINGLE_FILE` with pthreads and `-sMAIN_MODULE` on Emscripten 6.0.9 is expected to work (pthread Workers load the
  same `.js`; side modules stay separate files); the toolchain check settles it first.
- `safaridriver` allows one session at a time and needs remote automation enabled on the runner.
- Lazy schema compiling moves about a second of work to each other schema's first use after a settings change.
