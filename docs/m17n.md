# m17n

`engines/m17n/` builds ibus-m17n 1.4.40, the IBus front end of the m17n input-method library, with m17n-lib 1.8.6 and
m17n-db 1.8.10, as one engine module, `m17n.wasm`, whose 197 engines are the input methods ibus-m17n would offer on the
desktop. This page describes how it is built, how the module starts without a bus, its engines and their descriptors,
its settings and m17n's input-method variables, and its checks.

```sh
nix build .#ibus-web-m17n
nix build .#checks.x86_64-linux.m17n-imports
```

## Build

`flake.overlays.m17n`, which applies only to `pkgsWasm`, overrides nixpkgs' recipes and keeps their Autotools builds.
Local patches apply after nixpkgs' in two layers, `port` then `casts`, each sorted by filename, under
`engines/m17n/patches/m17n-lib/` and `engines/m17n/patches/ibus-m17n/`; a layer with no patch has no directory. The
[inventory](../engines/m17n/patches/README.md) gives each patch's reason.

### m17n-lib

`m17n_lib` is built static, with only its core and input-method libraries. configure reads `--without-gui` (as
`with_gui`; `--disable-gui` does nothing), which skips the checks for the GUI, font-layout and drawing libraries;
`--without-libotf`, `--without-fontconfig`, `--without-gd` and `--without-x` say no to each in case a check runs anyway.
libxml2, which m17n uses to serialise M-texts, ispell and wordcut, whose callers are a spelling module and Thai word
segmentation, are found through programs and test links the build machine could answer, so configure's cache variables
answer each `no`; none is reached from an input method. A cross build can't run `AC_FUNC_MALLOC`'s and
`AC_FUNC_REALLOC`'s test programs, and would substitute `rpl_malloc` and `rpl_realloc`, which m17n-lib doesn't define;
Emscripten's `malloc(0)` and `realloc(NULL, 0)` return pointers, so their cache variables answer `yes`. `--disable-nls`
leaves out gettext, and the `example/` programs aren't built.

configure runs the `m17n-db` program to learn `M17NDIR`, where the library reads its data. The overlay puts a script of
that name first on the build's path, printing `ibus-web-m17n-db`'s directory, so the data keeps that store path.

Two port patches serve the WebAssembly build. configure checked for pkg-config inside its GUI block, which
`--without-gui` skips, and stopped on the conditional left undefined; 0001 moves the check out. `load_external_module`
in `input.c` called `dlopen` for an input method's external module, a library in m17n's module directory. No such
directory exists here, and each attempt would print the loader's error in the host's console. 0002 checks for `dlopen`
outside the GUI block as well and, without it, fails each module's load as a missing file already fails; the overlay
answers `ac_cv_search_dlopen=no`. The library then refers to nothing of the dynamic loader, and to no module directory,
since only that code read `M17N_MODULE_DIR`. The methods that need a module, `ja:anthy` and `en:ispell`, are those m17n
lists as unable to load.

### m17n-db

`ibus-web-m17n-db` is the build machine's `m17n_db` output's `share/m17n`: the 210 input methods, their icons, charset
maps and tables, 7.6 MB. Its `scripts/` is left out, since their shell and awk would bring bash and gawk into the
module's data closure. m17n's per-user directory, `~/.m17n.d`, lies under the module's home, `/engines/m17n`; nothing
writes there.

### ibus-m17n

`ibus-engines.m17n` is configured `--with-gtk=no`, without GTK, Python or `wrapGAppsHook3`, with its data directory in a
`data` output. Its `LIBEXECDIR`, which only the setup tool's command line uses, is `/usr/libexec`, so nothing built from
the tree refers to the package's own output. From that configured tree, upstream's Makefile builds `libm17ncommon`
(`m17nutil.c`), and our sources compile with the flags make used for it, read from the generated Makefile.

`m17n.wasm` links `libm17ncommon`, `engine.c` and the module's sources, compiled with the same flags, with m17n-lib's
archives; `main.c`, which connects to the bus, isn't built. `default.xml`, from which ibus-m17n takes each engine's rank
and the methods it hides, is installed in the `data` output. The module's closure, which its distribution carries, is
`ibus-web-m17n-db`, the `data` output and the compiled schemas, and nothing else.

One port patch and one cast patch apply. `ibus_m17n_mtext_to_ucs4` converted a buffer it never terminated, so a lookup
table built from an M-text candidate group gained candidates made of whatever the allocation held; port 0001 terminates
it. The cast patch gives `ibus_m17n_engine_class_init` and `ibus_m17n_engine_init` the two-argument types GLib calls
them with, without which the first `CreateEngine` traps, and `ibus_m17n_engine_destroy` its declared type.

## Startup

`engines/m17n/module/module.c`'s `ibusweb_module_init` does what ibus-m17n's `start_component` does without a bus:

1. `ibus_m17n_init_common()` initialises m17n;
2. `ibusweb_m17n_variables_init()` applies the input-method variables from their settings
   ([Settings and variables](#settings-and-variables));
3. `ibus_m17n_get_component()` lists m17n's input methods and applies `default.xml`'s ranks and blacklist;
4. each listed engine's type, from `ibus_m17n_engine_get_type_for_name`, is registered with the factory.

ibus-m17n's GObject constructor for an engine opens its input method the first time, when the class has none yet. The
variables are in place before any input method opens. The constructor emits records, two hidden preedits and a property
update; the runtime gives an engine its context from its instance init
([runtime.md](runtime.md#protocol-dispatch-and-output)), so they reach that context. Listing the input methods parses
every `.mim`, so module init reads m17n's charset and coding tables, `global.mim` and each input method's `.mim`.

## Engines

The engines are those `ibus_m17n_list_engines` keeps: the input methods m17n can load, that `default.xml` doesn't rank
below zero (`zh:py`, `ko:han2` and `ko:romaja`; it ranks `ja:anthy` there too), and that declare no `candidates-charset`
variable, since upstream's check for a UTF-8 charset is always true and drops every method that declares one, on the
desktop as here. `ja:anthy` and `en:ispell` need an external module, so m17n lists them as unable to load. That leaves
197 engines, each keeping upstream's name, `m17n:<lang>:<name>`.

ibus-m17n's engine derives from `IBusEngineSimple` and offers it each key first, for compose sequences. The runtime's
`IBusEngineSimple` handles none ([runtime.md](runtime.md#ibus-layer)), so every key goes to m17n.

### Descriptors

`engines/m17n/descriptors/descriptors.c` is a WebAssembly program, run under Node at build time, linked with
libibus-web, ibus-m17n's `libm17ncommon` and m17n-lib, as the module is. It calls `ibus_m17n_init_common()` and
`ibus_m17n_get_component()`, and prints as JSON each engine's name, language, input method, rank and layout, and the
input method's variables from `minput_get_variable(lang, name, Mnil)`: each one's name, description, type, initial value
and valid values. It is built from ibus-m17n's configured tree in a derivation of its own, so that the schemas
`m17n.wasm` compiles in can come from its output: m17n-lib, then the program, then its output, then the schema
directory, then `m17n.wasm`. It runs with a 1 MiB stack: `mplist__from_file` keeps a 64 KiB read buffer on the stack,
the whole of Emscripten's default.

`descriptors.ts`, in the private workspace package `@ibus-web/m17n-descriptors`, turns that output into the module's
files, which `packages.ibus-web-m17n-descriptors` holds beside the program's output, `raw.json`:

| File                                                             | Holds                                                                          |
| ---------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| `engines.json`                                                   | the engine descriptors, for `mkEngineManifest`'s `engines`                     |
| `settings-paths.json`                                            | each engine's path for `org.freedesktop.ibus.engine.m17n`, for `settingsPaths` |
| `settings-schemas.json`                                          | the module's schema ids: ibus-m17n's, the panel's and every variable schema's  |
| `schemas/org.freedesktop.ibus.engine.m17n.variables.gschema.xml` | the input methods' variable schemas                                            |
| `variable-table.h`                                               | each variable, with its input method, schema and m17n type                     |
| `instances.txt`                                                  | every settings instance the module declares, one a line, for test harnesses    |

| Descriptor field | Value                                                                                                                                         |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `name`           | The engine's name                                                                                                                             |
| `languages`      | m17n's language, an ISO 639 code and so BCP 47 (`hi`, `sat`, `new`); `[]` for the `t:*` methods, which m17n's `t` marks as for any text       |
| `displayName`    | The language's English name from `Intl.DisplayNames` and the input method in parentheses, "Hindi (inscript)"; the bare input method for `t:*` |
| `keyboard`       | `{ layout: "default", passThrough: [] }`                                                                                                      |

m17n's `title` is the mode indicator (क for `hi:inscript`), not a name. ICU names no language for `ath`, `cmc`, `dra`,
`nsk` and `tai`, which take ISO 639's names: Athapascan, Chamic, Dravidian, Naskapi and Tai. Another language with no
name fails the build, as does a layout other than upstream's `default` and `default[lv3:ralt_switch]`, which both become
`default`. The module's default, the option `ibusWeb.engines.m17n.defaultEngine`, `m17n:t:latn-post`, Latin postfix
diacritics, which works on any keyboard, comes first; the rest are sorted by language, then input method.

## Settings and variables

ibus-m17n opens its relocatable schema, `org.freedesktop.ibus.engine.m17n` (`lookup-table-orientation`, the preedit
colours and underline, `use-us-layout`), once for each engine, in the engine's class, at
`/org/freedesktop/ibus/engine/m17n/<lang>/<name>/`, so each engine's settings are an instance of their own and a change
reaches its class at once. The descriptor step's `settings-paths.json` lists the 197 paths for `mkEngineManifest`'s
`settingsPaths`. ibus-m17n builds each path from the engine's GType name, which lowercases the input method's name, and
keeps an all-uppercase name, `sa:IAST`, as it is, since it retries that when m17n knows no input method by the
lowercased one; the step builds the paths the same way.

`use-us-layout` looks each key up in the runtime's US keymap by its evdev code, so the keys are those at their US
positions whatever the user's layout. AltGr keys (Mod5) are looked up there without it and reach m17n as `G-` keys.

41 of m17n-db's input methods declare variables; 34 of them are engines, with 53 variables (`candidates-group-size`,
`trim-last-halant`, `tone-mark-on-last`, `use-surrounding-text`, `level`, …). The descriptor program reads each engine's
with `minput_get_variable(lang, name, Mnil)`, and for each engine that has any, the step writes a fixed-path schema,
`org.freedesktop.ibus.engine.m17n.<lang>.<name>`, at the engine's path with `variables/` added:

| m17n type | Key type | Constraint                                                       |
| --------- | -------- | ---------------------------------------------------------------- |
| integer   | `i`      | its valid values as one range; m17n-db's are 0–1 or 0–2, or none |
| symbol    | `s`      | its valid values as choices                                      |
| text      | `s`      | none                                                             |

Defaults and descriptions are the input method's. A variable whose name isn't a valid GSettings key, one without an
initial value, integer values that aren't one range, or a default outside its values fails the build. The schemas
compile with ibus-m17n's and the panel's into the module's schema directory, and `settings-schemas.json` lists them all,
so the page stores them as it stores any settings.

`engines/m17n/module/variables.c` applies them from the step's `variable-table.h`, which lists each variable with its
input method, schema and m17n type; the schema alone can't give the type, since symbol and text variables are both `s`
keys. At module init, before ibus-m17n lists the input methods, it reads every one and calls `minput_config_variable`;
on a schema's `changed` signal it does so for the changed key. m17n copies the configured values into each input context
when it is made and again when it is reset. ibus-m17n makes a context per engine and resets it on focus-out and on
Reset, so a change reaches every context made afterwards, including those of engines already in use, and an existing
context at its next focus-out or Reset. Only a composition already under way keeps the old value. `minput_save_config`
is never called: the page's settings are the only store, and `~/.m17n.d/config.mic` is never written.

## Distribution

`ibus-web-m17n-dist` (`engines/m17n/dist.nix`) is `mkEngineManifest` over `m17n.wasm`, with the descriptor step's
`engines.json`, `settings-paths.json` and `settings-schemas.json`. Its 197 engines start with `m17n:t:latn-post`, the
module's default. The schema list is a file because the variable schema ids exist only once the descriptor program has
run; the manifest lists its 36 schema ids as any manifest does.

The data closure is `ibus-web-m17n-db`, ibus-m17n's `default.xml` and the compiled schemas: three archives, 7,708,375
bytes installed and 1,515,439 as Brotli. `m17n.wasm` is 235,262 bytes. The manifest declares no engine threads and a 29
MiB heap, from `checks.m17n-host`'s heap peaks of 25,180,288 bytes asserting and 25,178,368 released with every engine
open in one Worker; its memory comes to 77 MiB.

The licence is `GPL-2.0-or-later AND LGPL-2.1-or-later`: ibus-m17n's, and that of m17n-lib, linked into the module, and
of m17n-db, its data.

The module ships as `@ibus-web/engine-m17n` (`packages/engines/m17n/`): `nix build .#npm.engine-m17n` copies
`ibus-web-m17n-dist` in as `dist/` and both licence texts into `LICENSES/`, and `npmTarball` fails unless
`package.json`'s `license` is the module's. It exports `manifest.json`, `m17n.wasm`, `settings.json` and `data/*`; the
tarball is 1.6 MB.

## In the browser

The demo serves the distribution beside the other modules. Its picker gives m17n's engines one group per language,
labelled `m17n · <language>` with the language's English name from `Intl.DisplayNames`, in the order the manifest first
lists each; the `t:*` methods, which declare no language, stay under `m17n`. Its settings form shows, of the paths an
engine owns (those holding the engine name's components as consecutive segments, compared in lower case, since
`sa:IAST-vedic` lives at `sa/iast-vedic/`), only the selected engine's: its instance of
`org.freedesktop.ibus.engine.m17n` and, where its input method has variables, their schema at `variables/` below it. The
panel's schema, which no engine owns, is always shown. A saved variable reaches every input context made afterwards and
an existing one at its next focus-out or reset, since ibus-m17n resets its m17n context then and a reset takes the input
method's configured values; only a composition already under way keeps the old value.

Module init reads about 212 files, 2.5 MB, at every start. In a browser, every start after the first reads them from
IndexedDB. `m17n.spec.ts` restarts the module once its data is installed and times the page from Restart module to
`ready`; the figures are from the second of two runs: 2906 ms in Chromium 153.0.8010.12, 1014 ms in Firefox 155.0 and
1147 ms in WebKit 26.6, under the Nix sandbox's Playwright 1.63.0 on an AMD Ryzen 9 9950X3D (32 logical CPUs).
Chromium's start took about 2.5–3 times the others in both runs; why is not investigated, and the runs shared the
machine with the rest of the Playwright suite. The figure to set beside them is the 561–718 ms of `m17n-host` under
Node, which times a `worker_threads` host from its start through `Init` and the first `CreateEngine`, with the data
installed from its archive and no page or IndexedDB. The runs differ by up to about 21% (Firefox 951→1014 ms, WebKit
944→1147 ms); there is no target until there is a baseline.

## Checks

- `checks.m17n-cast-audit` audits ibus-m17n's `m17nutil.c` and `engine.c` with the module's sources, using the engine's
  configured `config.h` and the flags make uses, against `engines/m17n/cast-audit.jsonc`, which is empty; and the
  sources of `libm17n-core` and `libm17n`, with the library's own, against `engines/m17n/m17n-lib-cast-audit.jsonc`:
  seven casts through `M17NFunc`, the type m17n stores every function as, each with its reason.
- `checks.m17n-imports` checks `m17n.wasm`'s imports against the runtime's export list, and that it imports nothing of
  the dynamic loader (`dlopen`, `dlsym`, `dlclose`, `dlerror`).
- `checks.m17n-data-closure` checks that the module's closure is exactly `ibus-web-m17n-db`, the `data` output with
  `default.xml` and the compiled schemas, with no libraries, headers or modules.
- `checks.m17n-descriptors` runs the descriptor step's Vitest tests: display names, settings paths (`sa:IAST` included),
  ordering, variable keys and what fails the build, the schema XML and the variable table; and, on the built output, 197
  engines with the default first, 197 settings paths, and 34 variable schemas with 53 keys.
- `checks.m17n-golden` runs a g_test program under Node with the real `m17n.wasm` and its data. Init declares every
  instance the module's metadata does, from the descriptor step's `instances.txt`, and stores Telex's
  `tone-mark-on-last` as 1 and Cangjie's `candidates-group-size` as 2. The cases: an engine's first `CreateEngine` emits
  its hidden preedits and property update on its own context; Latin postfix (`a'` gives á); Hindi InScript's direct keys
  and its halant in the preedit; Vietnamese Telex's preedit; Thai Kesmanee reading the surrounding text and, after a
  tone mark, deleting it before committing another; Cangjie's lookup table, and its paging with groups of two; AltGr and
  `use-us-layout` through the runtime's US keymap; `use-us-layout` on Hindi InScript leaving Marathi InScript's instance
  alone; Telex putting the tone of `hoaf` on the last vowel from Init, where VNI, at its default, puts it on the first;
  and a variable changed before VIQR's first context reaching it. Every record but a log or a settings write must be on
  the case's context, and a warning from the module fails the program.
- `checks.m17n-engines` makes each engine the descriptors list, in the same Worker, types `a`, `1`, space and BackSpace,
  and destroys it; a warning from any of the 197 fails it. The engine names come from `engines.json`, so the module and
  its manifest are checked against each other: every descriptor names an engine the module registered.
- `checks.m17n-host` runs the distribution through a Node Worker host and the test page, on each runtime build, with
  `Init` declaring every instance the metadata lists, 232 of them in 22,378 bytes, within the transport's 64 KiB request
  slot. `t:latn-post` composes `á` and commits it with the Space; `hi:inscript` commits `क`; `vi:telex` makes `việt`,
  and puts the tone of `hoaf` on the first vowel unless `tone-mark-on-last` from `Init` puts it on the last, a change to
  it reaching a context made afterwards and an existing one after a focus-out; `th:kesmanee` refuses a tone mark with
  nothing before the caret and takes it after the surrounding text's `ก`; `zh:cangjie` lists `日` and `曰` for `a` and
  commits `日`. A relocatable instance's value from `Init`, and a `SettingChanged` at `t:latn-post`'s path, reach that
  engine and not `vi:telex` beside it; what an engine emits while being made reaches the context it is made for. Every
  engine open in one Worker stays within the declared break, with no engine threads. It records each start, 561–718 ms
  with the data installed from its archive.
- The demo serves the distribution, and `examples/demo/test/e2e/m17n.spec.ts` runs in Chromium, Firefox and WebKit:
  m17n's language groups in the picker; Hindi from inscript's keys; Vietnamese composed and committed on Space; a Thai
  tone mark on a consonant already in the textarea, which reaches the engine only as surrounding text; a settings form
  holding the selected engine's instance and variables, not another's; and Telex's `tone-mark-on-last` saved in the form
  and reaching the textarea once it has lost focus after the save and regained it; it times a restart from IndexedDB,
  once the page shows persistent storage.
- `checks.typescript-npm` packs `@ibus-web/engine-m17n` with both licence texts.
