> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Leave M0 with nothing temporary in it: every test structured, every
check run by hk from the hooks and the flake alike, the spike's Worker host
rebuilt as `@ibus-web/worker-host` on Effect 4 with its scenarios as tests,

**Architecture:** hk (`hk.pkl`) becomes the single place checks and

`hk fix --all`, and `checks.hk` runs `hk check --all` in the sandbox. Tests
are GoogleTest (C/C++ without GLib), GLib's g_test (C that links GLib) and
Vitest (TypeScript). A Vitest shim runs WASM test programs in Chromium and
Firefox (browser mode, nixpkgs' Playwright browsers) and under Node, and
turns each program's GoogleTest JSON report or g_test TAP stream into one
Vitest result per case. `@ibus-web/worker-host` is a pnpm package in Effect 4
that carries the spike host's behaviour (instantiation, pool top-up, the
sleeping request loop, the wake relay, crash reports, storage, the engine-data
install protocol, the writer lock) and its scenarios as Vitest suites under
Node and both browsers.

**Tech Stack:** Nix flake (flake-parts, import-tree), FlakeHub inputs and
FlakeHub Cache, hk 1.57.0 + pkl 0.31.1, oxfmt 0.61.0, oxlint 1.80.0,

## Global constraints

- nixpkgs: whatever `flake.lock` pins; Task 1 moves it to the latest FlakeHub release (an ordinary flake update), and later tasks build on that lock.
- Flake inputs come from FlakeHub (`https://flakehub.com/f/<org>/<project>/<ver>`) when the project publishes there **and** its latest FlakeHub release is current with upstream; otherwise from `github:`.
- Emscripten is `ibusWeb.toolchain.emscripten` (nixpkgs' build plus `modules/emscripten/patches`), used by the cache, the cross stdenv, the dev shell and clangd; never `pkgs.emscripten` or `pkgsBuildBuild.emscripten` directly. Small fixes to Emscripten are allowed when tracked upstream; no forked compiler or LLVM; never `-sEMULATE_FUNCTION_POINTER_CASTS`.
- Every WASM object is compiled with `ibusWeb.toolchain.commonFlags` (`-O2 -fPIC -pthread -fwasm-exceptions -mextended-const`; links also get Emscripten's minimum versions from Baseline Widely available, with a one-way Firefox floor of 126, each only for the environments the link's `-sENVIRONMENT` allows); check and test links add `-sASSERTIONS=1`.
- **Derive, don't hardcode:** versions, target prefixes, triples, store paths and symbol lists come from Nix evaluation or the build, never literals.
- Dendritic layout: every `.nix` file under `modules/` is a flake-parts module; modules share values only through `ibusWeb.*` per-system options and flake outputs. The runtime is a component at the repository root: each part has one directory, `runtime/<part>/`, holding its sources, its flake-parts modules and its tests; runtime-wide options are `runtime/options.nix`. TypeScript packages live under `packages/<name>/` (pnpm workspace) with their Nix modules beside them. Non-Nix files sit beside their module under plain names.
- Outputs: `packages.<system>` is not a mirror of nixpkgs' WASM builds (those are `legacyPackages.<system>.pkgsWasm`); our own derivations, including pinned tools, may be packages.
- Main modules are linked with `em++` (`$CXX`); C and C++ sources are compiled with `$CC -c`/`$CXX -c` first.
- §9.2 boundary rules: Workers load by URL, never inlined; **the page communicates only through the dedicated SAB and `postMessage`, never touches WASM memory, and the protocol never carries pointers into it.**
- Cross-origin isolation for browser runs: `Cross-Origin-Opener-Policy: same-origin` and `Cross-Origin-Embedder-Policy: require-corp` on every response.
- Storage (spec §5.6): IndexedDB values are `ArrayBuffer`s, never `Blob`s, and chunks stay under 64 KiB serialized; connections close on `versionchange`; the page opens no transactions on engine databases.
- **Structured tests:** GoogleTest for C and C++ that doesn't link GLib; GLib's g_test for C that links GLib; Vitest for TypeScript. No ad-hoc `main()` with CHECK macros, no `node:assert` scripts, no print-then-grep. Checks whose only assertion is that something builds or links, and lint-style consistency checks (exports, imports, REUSE, patch application), are not tests and stay as they are.
- **TypeScript first:** JavaScript that Emscripten doesn't read itself (`--js-library`, `--pre-js`, `--post-js`) is TypeScript; the JavaScript it reads carries JSDoc types and is type-checked. No new `node -e`/`python -c` scripts inlined in Nix.
- TypeScript: one pnpm workspace at the repository root; one repository-wide standard configuration, `tsconfig.base.json` at the root, that every `tsconfig.json` in the repository extends (directly, or through a package's own base that extends it) and overrides only where its files need to (environment `lib`/`types`, `rootDir`/`outDir`, `allowJs`/`checkJs` for Emscripten-read JavaScript); one `tsconfig.json` per environment directory (`shared`, `worker`, `page`, `node`); `strict`, `erasableSyntaxOnly`; checks run the emitted `dist/`. Versions pnpm can't know are asserted against nixpkgs (the `playwright` package equals `playwright-driver`; `packageManager` names nixpkgs' pnpm). Effect is a peer dependency of every package that uses it, at `^4.0.0` in the workspace. Ranges are ordinary caret ranges; `pnpm-lock.yaml` is what pins exact versions. Anything that must have one version across the repository (TypeScript, Vitest and its browser packages, Playwright, Effect, `@effect/vitest`, `@types/node`) is declared once in the `catalog:` of `pnpm-workspace.yaml`; repository-wide tools are `devDependencies` of the root `package.json` (`"typescript": "catalog:"`, …), and a package that needs one in its own manifest (a peer dependency, a package-level script) names it as `catalog:` too, never a version.
- Hand-written JavaScript/TypeScript uses modern syntax (Baseline "Widely available" ∩ the oldest supported Node).
- New files carry SPDX headers (`SPDX-FileCopyrightText: 2026 Synapdeck, Inc.`; `MIT OR Apache-2.0` for repository code; `LGPL-2.1-or-later` for `libibus-web`); files that can't hold a comment are annotated in `REUSE.toml`; `reuse lint` enforces it.
- Comments explain why, not what, and never refer to other files, this plan or its history.
- `nix flake check` passes at the end of every task. Flakes only see git-tracked files: `git add` before `nix` commands.
- Stage named paths only (never `git add -A`/`.`/`commit -a`); check `git diff --cached --stat` before committing; the user's environment stages files as they change, so commit with `git commit -- <paths>`. The user edits files concurrently: leave changes you didn't make; never `git checkout`/`restore`/`stash`/`reset --hard`.

## Decisions fixed here (later tasks rely on them)

**Test frameworks.** GoogleTest from `pkgsWasm.gtest` (static, `gtest.pc`,
no death tests: emcc doesn't define `__linux__`). WASM GoogleTest programs
link with `-sPROXY_TO_PTHREAD` so tests run on a pthread and the program's
own thread (a Worker's or Node's main thread) keeps its event loop for
IndexedDB, `postMessage` and post-js callbacks. GLib-linked C keeps g_test
(TAP). TypeScript uses Vitest 5.0.3; Effect code tests with `@effect/vitest`.

**The test-program shim** (`@ibus-web/test-programs`, replacing
`@ibus-web/test-browser`): Nix hands Vitest a manifest
(`IBUS_WEB_TEST_PROGRAMS`, a JSON file path) listing program directories, each
with `<name>.js`, `<name>.wasm`, optional `<name>.args`, and a format
(`gtest-json` or `tap`). For each program and each configured environment
(`node`, `chromium`, `firefox`), the shim runs it, then declares one Vitest
test per reported case (`<program> › <suite>.<case>` or the TAP test name),
passing or failing with the case's own message; a program that crashes,
times out or reports nothing is one failing test named after the program.
Programs named `<prefix>.<n>` run in order in one storage context (the
browser origin's storage, kept between them; in Node, one host directory);
every other program starts with the origin's storage cleared
(`indexedDB.databases()` → delete each, before it starts).

**How a GoogleTest program reports.** A shared harness library,
`ibus-web-gtest-main` (C++ + a JS library, built in Nix), provides `main()`:
it runs `RUN_ALL_TESTS()` with `--gtest_output=json:/tmp/gtest-report.json`,
reads the file back and hands its text to the host with a JS import that runs
on the program's main thread (`MAIN_THREAD_EM_ASM` / proxied sync call), which
in a browser posts `{ kind: "report", format: "gtest-json", text }` to the
page and under Node writes it to the path in `IBUS_WEB_TEST_REPORT`, then
exits with GoogleTest's status. A program's last report wins; stdout/stderr
are kept and shown only for failures.

**hk.** `hk.pkl` at the root imports a local, Nix-generated copy of hk's pkl
package (hk's `Builtins.pkl` is generated, not shipped, and the `package://`
form can't resolve in the sandbox): `amends ".hk/pkl/Config.pkl"` and
`import ".hk/pkl/Builtins.pkl"`, where `.hk` is a git-ignored symlink the dev
shell makes to `packages.hk-pkl` (hk 1.57.0's `pkl/` with `Builtins.pkl`
generated by its `scripts/gen_builtins.py` and pkl 0.31.1) and the sandbox
check makes the same way. `checks.hk` copies the flake source, `git init`s
and `git add`s it, sets `HOME`/`HK_STATE_DIR`/`HK_CACHE_DIR` into `$TMPDIR`,
and runs `hk check --all`. The flake's `formatter` runs `hk fix --all`.

**Effect 4 in the Worker host.** The host is a scoped Effect program whose
scopes follow spec §5.5.1; the request loop is one synchronous section (spec
§5.5.2) entered with `Effect.sync` over plain functions; the pool top-up is
the only asynchronous excursion. Configuration (limits that tests must
shorten) is a `Layer`, never module-private constants.
